# Current direction

## Meaning

This document carries TunnelTend's current near-term movement while no separate workplace owns it. The immediate outcome is a public, source-complete pre-release repository whose hosted CI is green, followed by bounded Windows lifecycle qualification, branding co-design, and an evidence-backed first release. It narrows sequence without shrinking the Vision.

## Current outcome

1. Publish the coherent PowerShell source repository to `Wolfsblvt/tunneltend`.
2. Consume hosted CI for the exact pushed commit and repair candidate-owned failures.
3. Run the local disposable-Windows validation carrier against that exact commit.
4. Reconcile any Windows findings into source and rerun affected evidence.
5. Complete owner co-design for icon, SVG, palette, voice, and public presentation.
6. Cut `v0.1.0` only after the release checklist and candidate evidence support it.

## Constraints

- Do not bundle the official OpenAI client.
- Do not publish a release merely because source CI is green.
- Do not weaken digest verification, process ownership, secret references, or read-only grammar to make tests pass.
- Keep the default autonomous experience: logon startup, watchdog recovery, and verified official-client updates.
- Preserve the no-hand-written-JSON normal journey.

## Not now

- A tray application or graphical dashboard.
- Non-Windows automation backends.
- A hosted TunnelTend service.
- Automatic source-control, package, build, migration, or container update strategies.
- Package-manager publication before the direct release route is proven.

## Completion boundary for this tranche

This tranche is complete when the public repository contains the exact accepted source, hosted CI is terminal and green for that commit, release artifacts build reproducibly, the local validation carrier is ready, and every unobserved Windows behavior remains clearly assigned to the Windows qualification session.
