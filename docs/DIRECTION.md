# Current direction

## Meaning

TunnelTend 1.0.2, the public Home and dedicated Docs Home are live. The owner-selected automatic future-client capability is delivered: compatible newer official releases can reach local users and accurate public guidance without a per-version repository edit or owner ritual. Local verified staging remains independent of central CI. Current Work and natural-use follow-through live in the shared workplace; the Vision and autonomous local-manager scope remain unchanged.

## Delivered outcome

1. Local maintenance resolves the latest stable official client and validates its actual distribution and required command behavior before replacement. Session intent, rollback, opt-outs and existing same-version bytes remain protected.
2. Daily Windows qualification exercises actual binaries and records separate source-build and published-package results. Distribution, credential-free CLI, owned fleet and connected consumer are distinct outcomes; unexercised boundaries remain explicit.
3. Retained native evidence and official asset-identity history reach the existing accepted-main website publisher. Freshness, expiry, outage and unknown history are disclosed without a local update gate or a second publisher.
4. The live Home, dedicated manual, public installer and latest stable distribution share the complete setup and adoption guidance. Optional upstream capabilities do not expand TunnelTend's credential model or scope. Wolf Ops retains hosting/provider custody.

The Docs/FAQ/upkeep repair is delivered. The automatic-client implementation and four independent security-review repairs reached the 1.0.2 release. Its qualified Windows package covers actual 1.0.1 adoption, the installed native task host, official 0.0.17→0.0.18 update, same-version retention, explicit rollback and uninstall at their recorded boundaries. Natural sign-in, sleep/resume and remote echo retain their earlier client-version boundaries; they are not relabeled as new-client proof. Current published qualification separately identifies the package and adapter actually exercised.

The [automatic-release contract](upstream-compatibility.md) owns the distribution, evidence and publisher boundaries. [The 1.0.2 release account](releases/1.0.2.md) explains the delivered change. The first naturally published newer official release is later field confirmation under product-lead custody, rather than a calendar prerequisite or a per-version acceptance ritual. Actual upstream contract breakage still earns focused adapter repair; a new version number alone does not.

## Constraints

- Do not bundle the official OpenAI client.
- Preserve autonomous defaults, secret references, process ownership and read/plan/apply grammar.
- Preserve the no-hand-written-JSON normal journey for humans and local coding agents.
- Keep source, built packages, published distribution, public reporting and actual consumer operation distinct.
- Keep the reader-facing manual under `website/` distinct from maintainer and product truth under `docs/`.
- TunnelTend owns product copy, identity, manual, deployment through admitted hosting, reader/install evidence and rollback choice; Wolf Ops owns hosting/provider/DNS/credential admission, provider receipts and the recovery interface.

## Not now

- A tray application or graphical dashboard.
- Non-Windows automation backends.
- A hosted TunnelTend service.
- Automatic source-control, package, build, migration or container update strategies.
- Package-registry publication.

## Continuing operation

Ordinary installed use and the existing daily qualification/publication route carry future compatible official releases. Failure triage and any demonstrated repair remain with the TunnelTend Lead. The first natural newer-release encounter should confirm that the unchanged released package and existing publisher process it without repository edits or owner intervention. Source, native artifacts, failure notification, public projection and connected operation retain their separate evidence boundaries.
